# История изменений

## Версия 3.1.8

- Браузерные тесты переписаны с `@playwright/test` на Go через
  [playwright-go](https://github.com/mxschmitt/playwright-go): отдельный
  модуль `e2e`, обычный `go test`, Node.js и `npm install` больше не нужны.
  Проверки через REST API декодируют ответы в общие структуры `web-ui/api`;
  `make vet` проверяет и этот модуль.
- Создание сервера проверяет порт и подсеть до сохранения, а не при запуске:
  порт вне 1–65535 и подсеть, которая не является IPv4 CIDR с местом хотя бы
  для одного клиента (не длиннее `/30`), отклоняются с `400`, а подсеть,
  пересекающаяся с подсетью другого сервера (совпадает, содержит его или
  лежит внутри), — с `409` и именем этого сервера. Правила общие для формы
  и бэкенда (`api.ParseSubnet`, `api.SubnetsOverlap`); форма при открытии
  сама подставляет свободную подсеть.
- Ошибка запуска сервера показывает причину: из вывода `awg-quick` берётся
  stderr упавшего шага (например, `Line unrecognized: …`) вместо голого
  `exit status 1` и без трассировки, предупреждения о userspace и баннера.

## Версия 3.1.7

- Счётчики трафика сервера и клиентов считаются из одного источника —
  `awg show <iface> transfer`. Раньше сервер брал байты из `ifconfig`
  (расшифрованная полезная нагрузка внутри туннеля), а клиенты — из
  `awg show` (зашифрованный UDP снаружи, с заголовками, handshake и
  junk-пакетами), и сумма клиентов на 4–5 % превышала цифру сервера. Теперь
  сервер — сумма своих пиров
- Над формой создания сервера появилась сворачиваемая панель «Мониторинг»
  (открыта по умолчанию): пять графиков за последние 5 минут — исходящий и
  входящий трафик VPN суммарно по всем серверам (текущая скорость сверху,
  всего передано снизу), загрузка CPU (число ядер снизу), RAM и диск с данными
  (занято / всего снизу). История хранится только в браузере и начинается
  заново при перезагрузке страницы; бэкенд ничего не накапливает.
- `GET /api/traffic` дополнен: в `server_traffic` к округлённым `rx`/`tx`
  добавлены точные `rx_bytes`/`tx_bytes` (те же числа `ifconfig`, из которых
  фронтенд считает скорость), а в новом поле `system` — мгновенные показания
  хоста через `gopsutil`: накопленное процессорное время (`cpu`), память и
  диск под `/etc/amnezia` (`memory`, `storage`). Новый пакет
  `internal/sysinfo`.
- Браузерные тесты сворачивают панель перед кликами (`startApp`), координаты
  в спеках сдвинуты на её свёрнутую высоту.
- Счётчики трафика в карточке сервера и в строках клиентов разделены на два
  значения с иконками загрузки/отдачи (те же, что на плитках мониторинга)
  вместо текстового `RX … · TX …`.
- Время работы: в строке интерфейса сервера показывается, сколько он поднят
  (`up 4h 12m`), в шапке — сколько работает сам бэкенд. Интерфейс отсчитывает
  время с момента, когда бэкенд впервые увидел его запущенным (старт из
  панели или первый опрос трафика), остановка обнуляет счётчик. В API — поле
  `uptime_seconds` в `server_traffic` у `GET /api/traffic` и в
  `GET /api/system/status`.
- Диалог конфигурации клиента переведён на вкладки с иконками: `.conf`
  с QR-кодом открывается первой, ссылка AmneziaVPN — второй; каждая вкладка
  строится один раз, без переключения состояния между представлениями.
- Исправлено «замирание» страницы после того, как вкладка больше минуты
  пробыла в фоне (другая вкладка, свёрнутое окно): по возвращении ничего не
  обновлялось и не реагировало на клики до изменения размера окна или
  перезагрузки.

## Версия 3.1.6

- Бэкенд разбит на пакеты по зонам ответственности в `internal`
- Socket.IO убран с обеих сторон: панель и так держала REST-опрос как
  запасной путь, а «живой» канал в wasm мог работать только через
  long-polling — тот же HTTP, только с лишней библиотекой, своим протоколом
  и исключениями в middleware. Теперь счётчики обновляются раз в 5 секунд
  одним запросом к новому `GET /api/traffic`, который заменил
  `GET /api/servers/traffic` и `GET /api/servers/{id}/traffic` (раньше
  запасной путь ходил за трафиком каждого сервера отдельно), список серверов
  — раз в 30 секунд и после каждого действия. Индикатор в шапке показывает `online`/`offline`
  вместо `live`/`polling`.
- Фронтенд разбит на пакеты по структуре страницы (`newserver`, `serverlist` →
  `serverentry` → `clientlist` → `cliententry` → `clientdialogs`); компоненты
  получают зависимости через `env.Env`, а не через общий объект `UI`.
- Интерфейс переведён на русский: язык берётся из настроек браузера
  (`navigator.languages`), для остальных — английский. Переводы лежат в
  `web-ui/translation/{en,ru}.json` и встроены в бандл через `lang` из Fyne;
  строки из общей валидации `web-ui/api` и ошибки бэкенда остаются на
  английском.

## Версия 3.1.5

- В подписях числовых полей формы стоит рекомендованное значение
  (`Jc (recommended 4-12)`, `S1 (recommended 15-150)`, `H1 (recommended 1)`), а
  в placeholder — допустимый диапазон движка. Источники: справочник параметров
  AmneziaWG 3.1 и README amneziawg-linux-kernel-module.
- Генератор параметров приведён к тому, что документация рекомендует для
  режима с защитой заголовков и `RandomTrailers`: все четыре паддинга
  `S1`-`S4` одинаковые, `H1`-`H4` = 1/2/3/4. Уже созданных серверов это не
  касается.
- Упрощённый режим формы больше не игнорирует `DEFAULT_MTU`: раньше он всегда
  слал зашитые 1420, из-за чего настройка бэкенда не действовала на серверы,
  созданные через UI. Расширенный режим подставляет то же значение в поле MTU
  при открытии формы.
- В расширенном режиме появилась галочка «Roll S1-S4 separately»: одинаковые
  паддинги, как рекомендует вендор, оставляют разницу между размерами типов
  сообщений равной штатной для WireGuard, и её можно восстановить по
  минимумам. Раздельные значения это маскируют ценой запаса на различение
  типов приёмником. По умолчанию — как в документации.
- Размер паддинга подбирается так, чтобы полноразмерный транспортный пакет
  укладывался в обычные 1500 байт: `S4` идёт в каждом пакете, поэтому на него
  остаётся `1440 − MTU`. Подсказка у поля MTU переписана — выше ~1425
  фрагментация неизбежна.
- Валидация теперь отвергает только то, что отвергнет сам движок: `H1`-`H4` —
  уникальные в `1-4294967295` (прежняя нижняя граница 5 отвергала как раз
  рекомендованную конфигурацию), `S1`-`S4` — `12-65535` вместо собственных
  ограничений 256/32, диапазоны тайминг-параметров — в `0-65535` и по
  возрастанию. Проверяется и в форме, и на сервере.
- Исправлено: вставка в любое поле роняла всё приложение, если панель открыта
  не по HTTPS и не с `localhost`. `glfw-js` берёт `navigator.clipboard` один
  раз, при инициализации пакета, а вне secure context его там нет — первое же
  чтение паникует и уносит с собой программу: канвас застывает на последнем
  кадре, дальше в консоли только «Go program has already exited», помогает
  лишь перезагрузка страницы. Ввод с клавиатуры до этого момента работает,
  из-за чего это похоже на баг вставки, а не на падение. Копирование,
  вырезание и вставка теперь идут через события `copy`/`cut`/`paste` браузера,
  которым ни secure context, ни разрешения не нужны, а `Paste` в контекстном
  меню поля — через собственный буфер панели. Заплатка в
  `web-ui/internal/fixes/clipboard_wasm.go`.
- Исправлено: колесо мыши над однострочным полем ввода снова прокручивает
  страницу.
- Исправлено: кнопки `Close`, `Cancel`, `Save`, `Yes`, `No`, `OK` в диалогах
  показывают курсор-руку.
- Исправлено: `server_id` клиента портился — `c.Params()` в fiber указывает в
  буфер запроса, который переиспользуется, и мусор попадал в конфиг. Лечится
  `Immutable: true`; уже испорченные конфиги чинит миграция схемы 4. На работу
  VPN не влияло, только на ответы API.
- Исправлено: автогенерация могла выдать одинаковые `H1`-`H4` — диапазоны
  делили граничные значения.
- Правила AmneziaWG переехали в общий модуль `web-ui/api`, туда же, где живут
  транспортные структуры: пределы, `Validate`, `ValidateCPS`,
  `GenerateObfuscation`. Раньше проверки и генерация существовали двумя почти
  одинаковыми копиями — во фронтенде и в бэкенде, с разными формулировками
  ошибок и разным набором проверок (серверная, например, вообще не проверяла
  зависящие от MTU границы `S1`/`S2`). Теперь копия одна, тесты на правила
  тоже одни, а каждая сторона тестирует только собственную обвязку.
- Сигнатурные пакеты `I1`-`I5` разбираются по грамматике `newObfChain` из
  `amneziawg-go` — и в форме, и на сервере. Раньше строка уходила в конфиг как
  есть, и опечатка всплывала уже у клиента: тоннель не поднимался. Диалог
  клиента при ошибке больше не закрывается, теряя ввод, а подсказка описывает
  сами теги.
- `make e2e` поднимает чистый инстанс сам: `make e2e-reset` удаляет контейнер
  с его volume и пересобирает образ. Инстанс отдельный от того, что оставляет
  `make run`; `make e2e-down` убирает его.
- В шапке рядом с заголовком видно, что за сборка открыта: тег релиза и номер
  сборки Fyne — `v3.1.5 · build 44`. Оба числа `fyne package` вшивает в бандл
  как метаданные приложения: тег он читает из `web-ui/FyneApp.toml`, номер
  сборки увеличивает там сам при каждой упаковке. Бандл, собранный обычным
  `go build`, метаданных не несёт и пишет `dev`, а не выдуманную версию.

## Версия 3.1

- Добавлена поддержка AmneziaWG 3.1: два новых переключателя в секции
  `[Interface]` — `RandomTrailers` (случайной длины «хвост» у каждого пакета,
  из-за чего рукопожатия теряют фиксированный размер в канале) и
  `DisableCookies` (никогда не отправлять cookie reply, пропускать проверку
  MAC2 под нагрузкой). Оба включены по умолчанию для новых серверов,
  доступны как галочки в форме создания сервера и пишутся из одних и тех же
  сохранённых значений в `.conf` сервера, в каждый клиентский `.conf` и в
  ссылку `vpn://`. `RandomTrailers` обязан совпадать на обеих сторонах —
  получатель без него молча отбрасывает удлинённое рукопожатие, — тогда как
  `DisableCookies` чисто локальный. Клиент старше AmneziaWG 3.1
  (AmneziaVPN < 5.0.1.5) не знает ни одного из этих ключей, так что снимайте
  галочки, если такие клиенты должны подключаться. Выключенный переключатель
  пишется как отсутствие ключа, а не `= off`, поскольку парсер до 3.1
  отвергает неизвестный ключ.
  Существующих серверов это не касается: в их сохранённых параметрах флагов
  нет, а отсутствие означает «выключено».
- Исправлено значение `protocol_version` в нативном экспорте конфига для
  AmneziaVPN: приложение сравнивает его со своей константой `awgV3`, а это
  буквально строка `"3.1"` во всех версиях, знающих про AmneziaWG 3 (начиная
  с 5.0.1.5). Прежнее `"3"` не совпадало ни с чем, из-за чего приложение
  показывало сервер со страницей настроек до 3.0 и помечало контейнер как
  устаревший.
- **Версии upstream AmneziaWG закреплены в `Dockerfile`**
  (`AWG_GO_VERSION=v3.1.20260828`, `AWG_TOOLS_VERSION=v3.1.20260812`) вместо
  клонирования `master`, поэтому пересборка больше не может незаметно
  подтянуть несовместимый или сломанный коммит. Другой тег задаётся через
  `--build-arg`.

## Версия 3.0

- Добавлена поддержка AmneziaWG 3.0 (защита заголовков): параметр обфускации
  `HeaderProtectionKey`, контроль требования S1-S4 ≥ 12 и необязательные
  «клиентские» тайминг-параметры (`ContentPaddingAddition`, `RekeyAfterTime`,
  `RekeyTimeout`, `RejectAfterTime`, `KeepaliveTimeout`,
  `MaxHandshakeAttempts`, `PersistentKeepalive`).
- **Ломающее изменение**: удалена поддержка режимов только-AmneziaWG
  1.0/1.5/2.0 и флагов запроса `awg2`/`awg3`. Включение обфускации теперь
  всегда означает полный набор параметров AmneziaWG 3.0 (защита заголовков
  обязательна, S1-S4 всегда ≥ 12). Уже работающих серверов это не касается —
  изменение затрагивает только вновь создаваемые.
- Добавлен экспорт конфига в нативном формате AmneziaVPN (ссылка `vpn://…`,
  новый эндпоинт `GET /api/servers/:id/clients/:clientId/link`, третья вкладка
  в модальном окне с QR-кодом клиента). Импортёр обычных `.conf` в официальном
  приложении `amnezia-client` всегда помечает импортированный конфиг AWG как
  устаревший контейнер `amnezia-awg` (отображается как «AmneziaWG 2.0», без
  защиты заголовков) вместо актуального `amnezia-awg2` — эта нативная ссылка
  несёт поля `container` и `protocol_version`, по которым приложение
  распознаёт сервер как AmneziaWG 3.0.
